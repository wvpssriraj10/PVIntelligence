Transfer Learning — Region B Adaptation

Pre-training on Region A (120 days) and transferring learned representations to Region B (18 days).

Core Academic Result
Section Purpose: Demonstrates our main machine learning innovation. Instead of requiring 120+ days of historical sensor data to train a solar forecasting model at a new site, we freeze the pre-trained recurrent layers from Region A and fine-tune only the top layers on Region B. This reduces data collection needs by 80% while achieving 53% lower RMSE compared to training from scratch.

Part 3 System Architecture & Methodology Documentation

Network Architecture

The base forecaster is a stacked LSTM → Dropout → GRU → Dense network consuming a 24-hour sliding window of irradiance, ambient temperature, cloud cover, and cyclical time features to predict upcoming solar generation.

Datasets & Data Scarcity

Region A comprises 120 days of hourly sensor readings (650 kWp array). Region B is deliberately limited to 18 days to demonstrate transfer learning efficacy in newly deployed, data-scarce solar regions.

Transfer Learning Methodology

Region A feature extractor weights are transferred to Region B, reducing training data requirements by 80% while beating scratch models by 53% in validation RMSE.

Explainability Protocol

SHAP computes marginal Shapley values for each feature, showing plant engineers exactly why a specific output was forecasted.
